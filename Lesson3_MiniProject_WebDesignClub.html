The Task

Your Web Design Club page already has visual feedback states you designed earlier in this unit. Today you'll make two of them actually work using JavaScript and the DOM — and you'll check your work against C.R.A.P., the same way you've checked every layout decision so far.

Part 1 · Setup

New today: git pull. So far you've only pushed work up to GitHub. Pulling is the opposite direction — it downloads the latest version of your repo from GitHub down to whatever machine you're on. You're on a VM today, so even though you're the only one who's touched this repo, your VM's local copy may not have your most recent commits on it. Pulling first means you're always starting from the newest version before you make new changes — skip it and you risk working on top of an outdated file, or hitting a conflict when you try to push later.
1
Pull your latest Web Design Club repo
Open your project folder in VS Code on the VM, open a terminal (Terminal → New Terminal), and make sure you're inside your project folder. Then run: 
git pull
This is the same repo you've been committing and pushing to all unit — you're not cloning it again or setting up a new remote, just syncing your local copy with what's already on GitHub. You should see a message telling you it's already up to date, or listing the files it just updated.
2
Create script.js
Add a new file, script.js, in your project folder (same level as your HTML file).
3
Link it in your HTML
Right before your closing </body> tag: 
<script src="script.js"></script>
4
Confirm the connection
In script.js: 
console.log("script.js is connected");
Open your page in the browser, open DevTools, and check the Console tab. You should see your message. If not — check your file path and script tag placement before moving on.

Part 2 · Guided Build: RSVP Confirmation

Find (or add) a button on your Web Design Club page inviting visitors to RSVP for the next meeting. You'll make it respond with a message inserted into the page — not a popup.

1
Give your button an id and an event attribute
<button id="rsvpBtn" onclick="handleRSVP()">RSVP for Next Meeting</button>
2
Write the function and test it with a log first
function handleRSVP() {
  console.log("RSVP button was clicked");
}
Click the button. Confirm the message shows up in the console before continuing.
3
Replace the console.log with a real DOM update
function handleRSVP() {
  const message = document.createElement("p");
  message.textContent = "You're on the list — see you there!";
  message.classList.add("feedback-message");

  const rsvpButton = document.getElementById("rsvpBtn");
  rsvpButton.after(message);
}
4
Style .feedback-message in your CSS file
Use your site's existing colors and font (repetition) so the message looks like it belongs on the page. Make sure it doesn't shove your layout out of alignment.
5
Handle the repeat-click case
Test clicking the button twice. If you get two messages stacked up, add a check so it only ever shows one (hint: check whether the message already exists before creating another).

Part 3 · Choice Feature

Pick one more interactive feature to add to your page. All three use the same core skills — getElementById, a function triggered by an event attribute, and a DOM update.

Member Counter
A button that increases a displayed "RSVP count" by 1 each time it's clicked, updating text already on the page.
Officer Spotlight Toggle
A button that shows or hides a club officer's bio text — created and inserted the first time it's clicked.
Custom (teacher-approved)
Propose your own interactive feedback element. Get a quick teacher check before you build — explain what triggers it and what feedback the user sees.

Part 4 · C.R.A.P. Self-Check

Before you commit, walk your two new features through this checklist:

  • Proximity — does each feedback element appear near the thing that triggered it?
  • Repetition — does it use your site's existing colors, fonts, and spacing?
  • Alignment — does adding it keep the rest of your layout intact, with nothing shoved out of place?
  • Contrast — is it noticeable without shouting louder than the rest of your page?

Part 5 · Commit, Push, Submit

This is the same repo and the same commit-and-push process you've used all unit — you're just adding a new commit on top of the work that's already there. In your terminal, inside your project folder:

1
Check what changed (optional but good habit)
git status
You should see script.js as a new file, plus your edited HTML and CSS files.
2
Stage your changes
git add .
This stages everything you changed — script.js and your edited HTML/CSS — for the next commit.
3
Commit with a clear message
git commit -m "Add RSVP confirmation and officer toggle with JS"
A commit is a saved snapshot of your project at this point — the message should describe what you just built, not just say "updates."
4
Push to GitHub
git push
This uploads your new commit to the same GitHub repo you've been using — no new setup needed. Refresh the repo page in your browser to confirm script.js and your changes are there.
5
Submit
Submit your repository link through the assignment page — the same link you've submitted before, since it's the same repo.

Stuck?

  • Check the console first — JavaScript will usually tell you exactly what went wrong and on what line.
  • Confirm your id in the HTML matches exactly what you typed in getElementById() — typos here are the #1 cause of "nothing happens."
  • Confirm your <script> tag is right before </body>, not in the <head>.
